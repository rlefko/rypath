# Pipeline Qualification

The audited historical `0ef51ba` study supports independent sampling with signed
temporal reconstruction as the viewer default, later selected in `4196288`.
Area1 remains an explicit candidate. The measured native-1080p performance target
is not met across the scene suite.

- **Quality:** at frozen source `0ef51ba`, independent/temporal has lower post-cap
  physical MSE than Area1/temporal in all six fixtures. The separate MetalFX
  results apply to our integration, with the limitations below.
- **Native timing:** only 2/90 primary runs meet complete-pipeline p95 ≤50 ms;
  none meet the 30 FPS threshold of approximately 33.33 ms. No scene/arm passes
  all three seeds.
- **Sustained timing:** four additional runs meet the planned minimum frame count
  and duration; none meets 20 FPS. Their independent audit also passes.
- **Scope:** these finite-reference quality, motion-anchor and timing measurements
  do not establish ghost-free motion or universal image quality.

The quality plan was recorded before measurement in ignored
`.cache/validation/golden-quality-001/plan.json`: twelve static scene/mode jobs
and five eligible motion jobs are complete. The separate native matrix has 108
complete reports, followed by four sustained runs. All identify historical source
**`0ef51ba`**, not a
later publication revision. The quality driver and headless runner serve different
purposes; neither automatically qualifies the [golden pipeline](golden-pipeline.md).

For review, start with the [quality tables](#audited-image-quality-results),
[time-to-quality clocks](#finite-references-and-descriptive-time-to-quality) and

## References, metrics and uncertainty

Reference samples use an independent `FrameSession`, advance absolute sample
indices, capture raw XYZ and accumulate in double precision before the
model-specific linear-RGB conversion. The fixed footprint does not grow with the
reference SPP or sample index. Equal-sized batches use separate sessions and
seeds. Reference batches require at least two batches and exact SPP divisibility.

For zero-based index i, evaluation seed i is `0x1000000000000000 + i + 1`.
Start-pose reference batch i uses `0x2000000000000000 + i + 1`; end-pose reference
batch i uses `0x3000000000000000 + i + 1`. These deterministic domains are disjoint.
Exact sample counts and finite values are checked; no failed samples are discarded.

For B batch means b and aggregate mean r, each pixel/channel's variance-of-mean
estimate is `sum((b-r)^2) / (B*(B-1))`. Its RGB/pixel average is the reported
reference MSE noise floor. Batch means, the aggregate and variance-of-mean are
retained as FLOAT EXRs. The reference is finite-budget evidence, not exact ground
truth. If its uncertainty obscures an arm difference, label that comparison
unresolved. Additional reference work must be a separately identified follow-up.

Per-frame metrics distinguish:

- **Raw physical RGB:** signed, unexposed raw conversion against the independent
  signed reference. No presentation clamp enters this metric.
- **Reconstructed physical RGB:** the separate reconstruction output against that
  same signed reference. Temporal output is signed float32; MetalFX has clamped
  negative/high input and half-float presentation storage.
- **Presentation RGB:** separately clamp both reconstructed RGB and the aggregate
  reference to `[0,65504]` before comparison. This is not the viewer's Reinhard or
  sRGB display transform. Nonlinear reference uncertainty is not estimated.

MSE averages all RGB components and pixels. NRMSE is
`sqrt(MSE / mean(reference_RGB^2))`; it is null for a zero-energy reference.
Signed channel-mean residuals expose changes that a scalar error average can hide.
Tone-map MSE is not implemented. Captures remain unexposed linear RGB; neither
EV nor display encoding is baked in, and reconstructed RGB is never converted
back through XYZ for capture.

The first four global frames are excluded from aggregate warm metrics when there
are more than four frames. Frames within a seed are correlated by reuse and
reconstruction. Average eligible frames within each seed first, then summarize
independent seed blocks. The reported block standard error is the sample standard
deviation of seed means divided by the square root of the seed count. Compare arms
or modes using paired seed-block differences. These descriptive errors are
conditional on a shared finite reference, not simultaneous confidence bounds,
proof of unbiasedness or a universal visual-quality criterion. Pixels and frames
must not be counted as independent replicates to inflate precision.

The frozen plan specifies physical NRMSE thresholds 0.10 and 0.05 for descriptive
time-to-quality postprocessing: require four consecutive static frames below
the threshold and report unreached thresholds as null. This is not an automatic
acceptance gate. Its clock sums measured pipeline intervals before readback;
session startup is reported separately, so it is not interactive end-to-end time.
The driver keeps `quality_pass_claimed:false` even when all jobs complete.

## Translation anchors and cuts

For motion, the frame count must be at least eight and divisible by four. With
q=frames/4, the schedule is:

1. Hold pose A for q frames, epoch zero.
2. Translate in world X through fractions `1/q` to `q/q` of the offset over q frames.
3. Hold pose B for q frames, epoch zero.
4. Cut back to A and hold for q frames, epoch one.

Orientation and lens settings remain fixed. Every request supplies the complete
camera snapshot and a known initial medium. Scenes with distinct medium interfaces
are rejected because this driver does not classify camera boundary crossings.
The scattering scene is therefore excluded from the five-scene motion study;
media motion remains unqualified.

The planned offsets are Cornell 0.1, many lights 0.25, glass 0.25, defocus 0.1 and
coated packet 0.25 world units. For example:

```sh
build/release/rypath-pipeline-qualification \
  --scene tests/fixtures/pbrt-render/cornell-box-adapted.pbrt \
  --output-dir .cache/cornell-motion-temporal-001 \
  --width 160 --height 90 --frames 32 --seeds 4 \
  --reference-spp 512 --reference-batches 8 \
  --reconstruction temporal --motion-offset 0.1
```

A and B have independently seeded reference batches. Every translation frame has
null quality metrics, including the last moving frame that reaches B. Timing,
phase, active camera pose, epoch, work counts and reset information remain recorded.
Anchor frames compare with the correct A/B reference. Motion aggregates are
explicitly mixed-pose, anchor-only means; `valid_metric_frames` differs from the
number of timed warm frames. Use per-frame anchor errors and retained B-hold
captures to assess settling and cut recovery. These do not establish quality
while moving or replace interactive ghosting assessment.

Area work accounting uses actual `history_used`: epoch cuts restart the cold
candidate count. Signed temporal history can also reset conservatively on camera
changes for defocus, media, transmission or mixed-material ambiguity. MetalFX
accepted/rejected history telemetry is null; zero counters are not match counts.

## Outputs, cost and timing scopes

`manifest.json` records input/settings provenance; `summary.json` determines final
completion. `frames.jsonl` retains every observed frame and its metrics, timings,
work, guide counters and resets; `seed-aggregates.jsonl` retains independent seed
blocks. Static references use `reference*.exr`; motion uses separate `start-` and
`end-` prefixes. Each seed/arm retains cold/final raw and direct reconstruction
FLOAT EXRs. Motion also captures the first and last B-hold frames. Source, sample,
epoch, seed, estimator/mutations, dimensions and build metadata accompany captures.

One new camera sample per pixel is not the total workload. Independent frames
perform N full evaluations for N pixels. Area with m mutations performs
`N*(5+m)` cold or `N*(6+m)` with eligible history, including fresh, temporal,
mutation and spatial replay. These evaluations include complete transport; shadow
rays and scattering events add work within them. The saved work counters, rather
than a display frame rate, determine actual throughput.

The frozen static plan executes about **9.898 billion full evaluations** across
six scenes and two modes, including regenerated references per job. The five
motion jobs add **366.336 million**. These are budget/accounting totals, not timing
or performance measurements. The driver does not share reference evaluation work
between separate invocations.

For every quality frame, wall timing starts before raw submission and ends at
reconstruction completion, before capture, metric reduction or EXR writing.
Reconstruction creation is included in the first frame's wall interval. Raw
session startup is recorded separately. Raw/reconstruction GPU timestamps cover
commands, not CPU gaps. The creation frame's combined GPU time is null because
the startup contract probe is not separately timed. Total job wall includes
readbacks and file output, while the sum of per-frame intervals excludes those
gaps. Quality runs capture both raw and reconstructed images to CPU every frame;
their reduced-resolution timings do not qualify native interactive performance.

Use the serial headless runner for a separate native timing study, after ensuring
GPU quiescence. It rotates scenes and arms across seeds and records complete
child reports, build/asset hashes, wall/RSS and available thermal observations:

```sh
python3 scripts/run_pipeline_benchmarks.py \
  --executable build/release/rypath-frame-benchmark \
  --scene cornell=tests/fixtures/pbrt-render/cornell-box-adapted.pbrt \

  --scene media="$qualification_scenes/media/scattering.pbrt" \
  --scene coated-packet=tests/fixtures/pbrt-render/packet-transport/coated-path.pbrt \
  --output-dir .cache/native-temporal-timing-001 \
  --width 1920 --height 1080 --frames 24 --warmup 4 \
  --seeds 31001,31002,31003 --reconstruction temporal --controls
```

This reproduces the audited short-run native matrix configuration below.
Runner defaults are 1920×1080, 24 measured frames, four warmup frames and those
three seeds. Its primary mode defaults to temporal; select MetalFX explicitly for
a separate matrix. `--controls` adds first-seed independent/raw-transport,
Area-one/raw-transport and Area-one/raw-RGB-conversion controls. The runner does
not compute reference-image error and does not read images back every frame.
The underlying benchmark can capture a final raw EXR with `--capture PATH`, outside
frame timing. Median/p95 use completed non-warmup pipeline frames; raw frame and
full-pipeline summaries remain distinct. Missing GPU timestamps remain explicit.
The benchmark binary must have its adjacent `rypath.metallib`; the build target
above supplies it. Process peak RSS is not total Metal memory. Short runs cannot
establish sustained thermal behavior or a population p95 bound.

The native-1080p target remains complete-pipeline p95 at or below 50 ms for 20
rendered FPS, or 33.3 ms for 30 rendered FPS. All reuse, mutation, guide and
reconstruction work counts. Upscaling/interpolation rates and display redraws
must be separate. Record misses and limitations as well as favorable cases.

### Finite references and descriptive time to quality

Estimated reference-noise NRMSE contributions are approximately **0.061–0.074 in
five scenes** and **0.027 in coated packet**. These are estimates of expected
finite-reference noise, not deterministic lower bounds on observed error. The
0.05 threshold lies below that estimated scale in five scenes; outcomes near or
below it cannot certify true physical error. No reference-floor subtraction,
reference extension, seed replacement or threshold relaxation was applied.

The fixed criterion is four consecutive literal static frames with physical
NRMSE **strictly below** 0.10 or 0.05. The recorded crossing completes at the fourth
qualifying frame. Each listed case reaches the criterion in **4/4 seeds** in both
searches; the ranges show the actual audited sums of pipeline intervals in

### Integration limits and viewer selection

The primary Apple-contract source review recorded at `c586c23` identified no
normal, motion, depth or exposure convention mismatch. That is a source-review
finding, not comprehensive framework qualification. Our baseline uses primary
pinhole surface guides and normal-incidence/F0 material proxies. It omits
reflected/transmitted-surface guide replacement and Fresnel blending discussed in
[WWDC 2026 session 359](https://developer.apple.com/videos/play/wwdc2026/359/).
The known negative/high input clamp also changes the spectral RGB supplied to
MetalFX. Consequently these MetalFX measurements apply to **our integration**,
not the framework generally. Exact GGX roughness correspondence and per-pixel
stochastic sampling versus global projection-jitter interpretation remain
unresolved.

Based on this bounded study, viewer revision **`4196288` defaults to independent
sampling plus signed temporal reconstruction**. Area1 remains an explicit
candidate, and MetalFX remains explicitly selectable. This is a practical default
decision for the measured implementation; it is not a universal estimator,
visual-quality, unbiasedness or FPS claim.

## Outcome and next work

The implemented pipeline is a tested baseline, and the 20–30 FPS scene-suite
target remains unmet. The bounded, weak-contrast Area target and full-path replay
do not earn their extra cost in this study. Stronger useful importance and cheaper
valid reuse/reconnection need their own support, density and weight checks.
Packet scheduling and guide/filter cost also remain measured optimization work.
MetalFX guide integration and broader signed reconstruction quality need separate
improvement and acceptance; upscaling has functional checks only, and frame
interpolation is not implemented or counted. This snapshot contains no new native
1080p Pavilion day/night stress-performance measurements. That broader stress
coverage remains open; the historical Pavilion quality failure is separate
evidence, and its investigation remains deferred in [status](status.md).
Offline acceptance also remains open.


## Paired reconstruction diagnostics

Use `--mutation-arms 0 --compare-reconstruction on --reconstruction temporal`
to submit each completed independent or zero-mutation Area frame to five
separate reconstruction histories. The primary signed filter uses history
limit 64 and five spatial passes. The additional signed streams use 1/0,
1/5, and 64/0 for history limit/spatial passes. The fifth stream runs
native-resolution MetalFX. Each signed stream uses the selected variance
policy. An unavailable filter fails the comparison.

The per-frame `comparison_filters` object reports each additional filter's
reset flag, GPU time when available, and signed-linear physical error at
reference camera poses. Final FLOAT EXRs identify the filter in their
filename and metadata. Use a separate frame-benchmark run for throughput.
Captures, additional reconstructions, and metric readback share this device
and affect subsequent frames.
